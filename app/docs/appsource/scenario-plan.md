## Prepare independent fixtures

1. Reserve a disposable validator-owned BC sandbox and a fresh synthetic company for each destructive scenario, or reset the owned company to a recorded baseline between runs. Record owner, environment ID, company, BC release/country and language.
2. Install the exact signed Attachments candidate and immutable Foundation dependency proven by #80; record their versions and SHA256 hashes. Install only the provider connectors needed by that scenario. Internal test apps do not form part of the customer offering.
3. Use synthetic data: connection code `AS81`, a unique run folder beneath a dedicated provider root, a customer named `AS81 Validation Customer`, an incoming document titled `AS81 Validation Document`, and text file `as81.txt` containing `Attachments validator sample`. No scenario depends on a previous row's records.
4. Provision separate setup, ordinary usage and denied-user identities. Obtain the exact Foundation API/license grants and provider permissions from #79; do not use SUPER to prove setup or usage. Source permission sets are `BIFROST Attach ori` (caption `Bifrost Storage`) and `BIFROST DataExch ori` (caption `Bifrost Data Exchange`). They do not establish minimum privileges; the former includes setup writes and the latter currently grants discovery reads.
5. Configure external storage through `Storage Setup Wizard` / `Storage Setup` on the module setup page. Use the production `External File Storage` backend, registered File Account, a dedicated Base Path and Enabled connection. Access the module through Foundation's registered Apps entry; the module page has `UsageCategory = None`, so do not assume Tell Me search exposes it.
6. Use the approved public Foundation transport and secure validator authentication supplied with the candidate. Retrieve `Help.Implementation.Get` for each wire type before constructing requests. Formal documents must include exact tested request envelopes and expected response fields, without private codeunit/table identifiers or credentials.
7. Capture response values, observable UI, file bytes/checksum and resource identifiers. For every row, create its fixture in Setup and remove only that fixture in Cleanup. Retain sanitized evidence and verify removal. Failed runs still require cleanup or a named cleanup blocker.
